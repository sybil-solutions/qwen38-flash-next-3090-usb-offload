`strata/0001..0005` were produced by diffing the live source trees against the pristine tag (no hand edits) and verified to reproduce those
trees byte for byte: `0001`+`0002` == the deployed `~/strata` working tree; `0003`+`0004` == the `~/strata-lockstep` tree the shipped engine was built
from before the host-tail step (`expert_source.cpp` and `verify.cpp` taken from the backups made right before the next experiment started editing them; the tree was
unchanged at that point, checked with `cmp`); `0005` brings `prefill.cpp` to the host-tail step's tree (sha256 `adfdddc8fa1c...` = `src/prefill/prefill.cpp` of `~/strata-lockstep` on the mini, checked 2026-10-12).
`scripts/verify-card-free.sh patches` re-runs the apply check.

**Config C (`0006`-`0019`, `shim/0001`-`0005`).** Base: `0006` applies to the tree after `0005`; every later patch applies to the tree after the one before it. They were made as the differences between the successive states of the files
the live engine `strata_d15a` was compiled from (the per-step source copies of the campaign: `runs/prefill600`, `runs/xport8` + the xport8 tree, `runs/decode5`..`decode15`; the server files from `~/strata-prefix-fix` and the deployed `~/strata/serve`), not
hand-written, in the order the steps were deployed. The end state is compared file by file with the live sources (`cmp`, 2026-10-15: `src/core/{verify,expert_source,layer}.cpp`, `src/program/generate.cpp`, `src/prefill/prefill.cpp`, `serve/server.py` ==
the files of `~/strata-decode15/src` and `~/strata/serve`; `kernels.cu/hpp`, `xport8*`, `path_select.hpp`, `ngram.cpp` == the xport8 / lockstep trees) and pinned by sha256 in [`results/verification/config-c-sha256.txt`](../results/verification/config-c-sha256.txt),
which `scripts/verify-card-free.sh patches` checks after applying the series to a pristine `v0.1.41` export. Things worth knowing:

- One comment line of `src/prefill/xport8_gpu_test.cpp` (patch `0008`) differs from the campaign's copy: the name of a private lab host was replaced by "a DGX Spark". The file is a test and is not in the hash manifest.
- The experiments that were built but did **not** ship on (HS_PREQ "prequeue", decode-ring statistics of the xport8 tree, the Decode13 per-blob staged miss job, the Decode3 MTP-in-EXL3 head, Decode17 batch work) are **not** in the series: the live engine does not contain them (its `verify.cpp` has no `HS_PREQ`, its `expert_source.cpp` is the Decode12 file).
  The xport8 tree's own `verify.cpp`/`expert_source.cpp` carry them; the shipped engine links the lockstep objects for those two files plus the Decode15 sources.
- `0010`, `0014`, `0015`, `0017` (the `KQ` part) are in the source of the shipped engine but behind env switches that config C does not set; `0010` is lossy.
- `0015` needs `exl3m_moe_rows_submit_gated` from a Metal library (`libexl3metal_d10`) that this repo does not carry, so `STRATA_D10_BGATE` cannot be switched on here.
- Device code: `0008` adds CUDA kernels to `src/prefill/kernels.cu`; the container build compiles them (the SASS of the rebuilt `kernels.cu` fatbin equals the live one after normalising nvcc's per-compilation names, [`results/verification/config-c-repro.md`](../results/verification/config-c-repro.md)).
